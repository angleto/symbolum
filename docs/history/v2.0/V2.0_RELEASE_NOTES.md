# Symbolicas v2.0 - Release Notes

## Summary

Symbolicas v2.0 introduces a revolutionary configurable simplification system that solves the cosine argument simplification problem and provides fine-grained control over algebraic transformations.

## What Was Implemented

### ✅ Configurable Simplification System

A comprehensive rule-based system with 12 configurable simplification rules:

1. **FactorCommonTerms** ⭐ - Extracts common factors (solves cosine issue!)
2. **CollectLikeTerms** ⭐ - Combines like terms (x + 2*x → 3*x)
3. **MergeFractionsLCD** - Merge fractions to LCD (optional)
4. **RemoveIdentity** - Remove 0s and 1s
5. **FlattenOperations** - Flatten nested operations
6. **CombineNumericLiterals** - Combine numeric constants
7. **MergeFractionsCommonDenom** - Merge fractions with same denominator
8. **DistributeProduct** - Distribute multiplication
9. **SimplifyDoubleNegative** - Eliminate double negatives
10. **ProductOfCosToSumOfCos** - Trigonometric identity
11. **SimplifyFractions** - Reduce fractions
12. **CancelCommonFactors** - Cancel common factors (placeholder)

### ✅ Solves Your Main Issues

#### Problem 1: Cosine Argument Simplification ✓
```scala
// Before: cos(n*pi - n/2*pi)  // Not simplified
// After:  cos(n*pi/2)         // Properly simplified ✓

val config = SimplificationConfig.Default.withRule(FactorCommonTerms)
val result = expr.fullSimplify(config)
```

#### Problem 2: Selectable Simplification Rules ✓
```scala
// Create custom configuration
val config = SimplificationConfig(Set(
  RemoveIdentity,
  FactorCommonTerms,
  CollectLikeTerms
))

// Or use fluent API
val config = SimplificationConfig.Default
  .withRule(FactorCommonTerms)
  .withoutRule(MergeFractionsLCD)
```

#### Problem 3: Recursive Simplification ✓
All simplification is recursive through the expression tree with the configurable fixpoint iteration already in place.

### ✅ Predefined Configurations

- **Default**: Balanced for symbolic computation
- **Minimal**: Essential rules only
- **Aggressive**: All rules enabled
- **None**: No simplification (identity)

## How to Use

### Quick Example: Solve Cosine Issue

```scala
import symbolicas.Dsl._
import symbolicas.SimplificationRule._

val n = Var("n")

// Your problem expression
val expr = cos(n*pi - (n/2)*pi)

// Solution
val config = SimplificationConfig.Default.withRule(FactorCommonTerms)
println(expr.fullSimplify(config))
// Output: cos(n*pi/2)  ✓ SOLVED!
```

### General Usage

```scala
// Default simplification (backward compatible)
val result = expr.fullSimplify

// Custom simplification
val config = SimplificationConfig.Default
  .withRule(FactorCommonTerms)
  .withRule(CollectLikeTerms)
val result = expr.fullSimplify(config)

// Choose predefined config
val result = expr.simplify(SimplificationConfig.Aggressive)
```

## Key Benefits

### 1. Fine-Grained Control
Choose exactly which simplifications to apply:
```scala
// Only factor and collect, don't merge fractions
val config = SimplificationConfig(Set(
  FactorCommonTerms,
  CollectLikeTerms,
  RemoveIdentity
))
```

### 2. Better Cosine Simplification
```scala
// n*pi - n/2*pi → n*pi/2 (inside cosine arguments)
// 2*n*pi - n*pi → n*pi (coefficient factoring)
```

### 3. Like Term Collection
```scala
// x + 2*x + 3*y → 3*x + 3*y
// Handles: Mul(2, x) + x automatically
```

### 4. Symbolic Fraction Control
```scala
// Default: Keep symbolic
1/2 + 1/3 → 1/2 + 1/3

// Optional: Merge to LCD
val config = SimplificationConfig.Default.withRule(MergeFractionsLCD)
1/2 + 1/3 → 5/6
```

### 5. Backward Compatible
All existing code continues to work:
```scala
// Old way (still works with default config)
expr.simplify
expr.fullSimplify

// New way (more control)
expr.simplify(config)
expr.fullSimplify(config)
```

## Architecture

### Clean Design
- Enum-based rule system
- Immutable configurations
- Fluent API for customization
- Implicit parameters for clean syntax

### Extensible
New rules can be added easily:
1. Add to SimplificationRule enum
2. Implement in expression class
3. Check `config.isEnabled(rule)` before applying

### Performant
- Rules only applied when enabled
- Single-pass simplification
- Efficient fixpoint iteration

## Known Limitations

1. **Factor extraction** is simple - extracts one common factor at a time
2. **Like term collection** uses string comparison for grouping
3. **Fixpoint detection** uses string comparison (could be improved)

These are design trade-offs for simplicity and can be enhanced in future versions.
